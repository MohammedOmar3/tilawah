# Quran Global MVP: Roadmap and Execution Guide

> **For Claude:** This is the index, not a task list. Execute the numbered plans below, each with `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Read `CLAUDE.md` and the spec before starting any plan.

**Goal:** Ship the Quran Global MVP described in `docs/superpowers/specs/2026-09-27-quran-global-mvp-design.md` for at most $20/month in hosting.

**Architecture:** Static Next.js on Cloudflare Pages, audio on R2 behind Cloudflare's cache, one Go service on Railway that only does clock sync, presence and telemetry. Playback position is derived from a fixed epoch and a looping programme, so no playback state exists anywhere.

**Tech stack:** pnpm workspaces, Next.js (App Router, static export), TypeScript, Tailwind, React Three Fiber + three-globe, Zustand, Zod, Vitest, Playwright; Go 1.24, chi, coder/websocket, slog.

## Execution waves

```
Manual Part 1 (M-S1 … M-S6)
        │
Wave 0  01 Foundation ─────────────────────────────── (one session)
        │
Wave 1  02 Data │ 03 API │ 04 Sync engine │ 06 Globe   (four sessions in parallel, one git worktree each)
        │
Wave 2  05 Web UI and integration ─────────────────── (one session)
        │
Wave 3  07 Deploy and operations ──────────────────── (one session)
        │
Manual Part 2 (M-E1 … M-E6) → 08 Production content → M-E7 … M-E11
```

### How to run a wave in parallel

For each plan in the wave, start a separate Claude Code session and say:

> Use superpowers:using-git-worktrees to create a worktree on branch `plan/NN-name` from `main`, then execute `docs/superpowers/plans/2026-09-27-NN-name.md` with superpowers:subagent-driven-development. When all tasks pass, open a PR to `main`.

Merge the wave's PRs before starting the next wave. Plans in a wave own disjoint directories (table above), and plan 01 installs every dependency up front, so the PRs don't conflict. If two PRs both touch `pnpm-lock.yaml`, merge one, then run `pnpm install` on the other and commit the lockfile.

### Rules for every executing session

1. Read `CLAUDE.md` and the spec sections the plan cites.
2. Work only in the directories your plan owns. If a task needs a change elsewhere, finish what you can and report it in the PR description.
3. A task is done only when its tests pass and `pnpm -r typecheck` and `go vet ./...` (where relevant) are clean.
4. Never do a manual step from `docs/SETUP-MANUAL.md`; if blocked by one, stop and report its ID.
5. Don't change a contract (spec §4) without updating the spec, TS schema, Go struct and fixtures in the same commit.
