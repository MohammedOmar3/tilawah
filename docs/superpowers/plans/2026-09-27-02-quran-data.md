# Plan 02: Quran Data Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate every static data file the web app needs: surah metadata, verified Uthmani text with a checksum manifest, and a development programme with generated test-tone audio and timings, so the whole app can be built and tested before real recitations exist.

**Architecture:** Node scripts in `tools/quran-data` read upstream files from `data/sources/tanzil/` and write to `apps/web/public/data/`. Pure functions (parsing, timing generation, WAV encoding) live in `src/lib/` with unit tests; thin entry scripts wire them to the file system. Generated JSON is committed; generated audio is not.

**Tech stack:** Node 22, TypeScript, tsx, Vitest, fast-xml-parser, `@tilawah/contracts`.

**Owns:** `tools/quran-data/`, `data/sources/tanzil/`, `apps/web/public/data/`, `apps/web/public/dev-audio/` (gitignored).

**Spec sections:** §2 (text source), §4.1 to §4.4.

**Manual dependency:** if `tanzil.net` is unreachable, stop at Task 1 and report **M-S4**.

### Task 6: WAV encoder and test-tone synthesiser

**Files:**
- Create: `tools/quran-data/src/lib/wav.ts`, `tools/quran-data/src/lib/wav.test.ts`

- [ ] **Step 1: Write the failing test**

```ts
import { describe, expect, it } from "vitest";
import { encodeWav, synthTrack } from "./wav";

describe("encodeWav", () => {
  it("writes a valid 16-bit mono PCM header", () => {
    const buf = encodeWav(new Int16Array(16000), 16000);
    expect(buf.toString("ascii", 0, 4)).toBe("RIFF");
    expect(buf.toString("ascii", 8, 12)).toBe("WAVE");
    expect(buf.readUInt16LE(22)).toBe(1);      // channels
    expect(buf.readUInt32LE(24)).toBe(16000);  // sample rate
    expect(buf.readUInt16LE(34)).toBe(16);     // bits per sample
    expect(buf.readUInt32LE(40)).toBe(32000);  // data bytes
    expect(buf.length).toBe(44 + 32000);
  });
});

describe("synthTrack", () => {
  it("has exactly durationMs of samples", () => {
    expect(synthTrack({ durationMs: 1500, sampleRate: 16000, beepAtMs: [0] }).length).toBe(24000);
  });
  it("is louder at a beep than between beeps", () => {
    const s = synthTrack({ durationMs: 2000, sampleRate: 16000, beepAtMs: [1000] });
    const rms = (a: number, b: number) => Math.sqrt(s.slice(a, b).reduce((x, v) => x + v * v, 0) / (b - a));
    expect(rms(16000, 16800)).toBeGreaterThan(rms(8000, 8800) * 3);
  });
});
```

- [ ] **Step 2: Run to verify it fails.**

- [ ] **Step 3: Implement.** `encodeWav(samples, sampleRate)` → standard 44-byte RIFF header + little-endian PCM. `synthTrack({durationMs, sampleRate, beepAtMs})`: a quiet 220 Hz hum (amplitude 0.05), a short 1 kHz tick (10 ms) at every whole second, and an 880 Hz beep (150 ms, amplitude 0.5, 5 ms fade in/out) at each `beepAtMs`. The per-second tick lets a person hear two devices drift apart.

- [ ] **Step 4: Run to verify it passes.**
- [ ] **Step 5: Commit** — `git commit -m "Add WAV encoder and test-tone synthesiser"`
