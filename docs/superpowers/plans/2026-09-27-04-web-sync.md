# Plan 04: Web Sync Engine Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The browser-side engine that keeps every listener at the same point: clock sync over WebSocket, a programme clock, drift correction, gapless-as-possible track changes, reconnects, and telemetry. No UI; plan 05 renders it.

**Architecture:** Pure, dependency-injected TypeScript. Time (`now`), timers, randomness, the WebSocket constructor and the audio element factory are all injected so every behaviour is unit-tested against fakes in simulated time. A Zustand store is the only thing the UI reads. `createListeningSession()` is the single entry point plan 05 calls.

**Tech stack:** TypeScript (strict), Zustand, Zod (via `@tilawah/contracts`), Vitest + jsdom.

**Owns:** `apps/web/lib/sync/`, `apps/web/player/`.

**Spec sections:** §3.1, §4.4, §4.5, §5.1 to §5.4.

**Uses from contracts:** `Programme`, `Timings`, `ClientMessage`, `ServerMessage`, `compileProgramme`, `positionAt`, `ayahAt`.

```ts
describe("ClockSync", () => {
  it("uses the lowest-RTT sample of a burst", () => {
    const cs = new ClockSync();
    cs.acceptBurst([
      { c0: 0, s: 5100, c1: 200 },  // rtt 200 → offset 5000
      { c0: 300, s: 5330, c1: 360 }, // rtt 60 → offset 5000
      { c0: 400, s: 5500, c1: 600 }, // rtt 200

    expect(cs.offsetMs).toBe(5000);
    expect(cs.rttMs).toBe(60);
  });
  it("rejects a later burst whose best RTT is > 1.5× the best seen", () => {
    const cs = new ClockSync();
    cs.acceptBurst([{ c0: 0, s: 5030, c1: 60 }]);
    cs.acceptBurst([{ c0: 1000, s: 7000, c1: 1200 }]); // rtt 200 > 90
    expect(cs.offsetMs).toBe(5000);
  });
  it("accepts a worse burst if the last accepted sample is older than 15 minutes", () => {
    const cs = new ClockSync();
    cs.acceptBurst([{ c0: 0, s: 5030, c1: 60 }]);
    cs.acceptBurst([{ c0: 900_001, s: 905_101, c1: 900_201 }]);
    expect(cs.offsetMs).toBe(5000);
    expect(cs.rttMs).toBe(200);
  });
  it("is unsynced until the first burst", () => {
    expect(new ClockSync().synced).toBe(false);
  });
});
```

### Task 4: SyncSocket (protocol, bursts, heartbeat, reconnect)

**Files:** Create `apps/web/lib/sync/socket.ts`, `socket.test.ts`

- [ ] **Step 1: Write failing tests** using `FakeTime` and `FakeServer`:
  1. `connect()` sends `hello{v:1, anon, programme}` first; `onWelcome` fires with the server's programme version.
  2. After `welcome`, an 8-ping burst runs 100 ms apart; with `serverOffsetMs = 5000`, up 30 ms, down 70 ms, the resulting `ClockSync.offsetMs` is within 20 ms of 5000 (asymmetry bound).
  3. `resync()` sends a 3-ping burst; one also runs every 5 minutes.
  4. `hb` is sent every 45 s, and nothing else is sent while idle.
  5. `setPlaying(true)` sends `state{playing:true}` once; repeating the same value sends nothing.
  6. `server.drop()` → reconnects after `backoffDelay`, re-sends `hello`, re-sends the current `state`, runs an 8-ping burst; attempt counter resets after a successful `welcome`.
  7. A `programme` message calls `onProgrammeChanged(version)`.
  8. Invalid server JSON is ignored (validated with `ServerMessage.safeParse`).
  9. `close()` stops timers and does not reconnect.
  10. `sendStat({rttMs, offsetMs, errMs})` sends a `stat` message.
- [ ] **Step 2: Run to verify they fail.**
- [ ] **Step 3: Implement** `new SyncSocket({ url, anon, programmeVersion, clockSync, deps: { WebSocket, now, setTimeout, clearTimeout, setInterval, clearInterval, random } })`. Ping ids are incrementing integers; `c` = `now()` at send; on `pong`, look up the pending ping by `id` and use `now()` at receipt as `c1`. A burst completes when all pongs arrive or 3 s pass; partial bursts are accepted if at least 3 samples arrived.

### Task 7: Audio engine

**Files:** Create `apps/web/player/audio-engine.ts`, `apps/web/player/audio-engine.test.ts`

- [ ] **Step 1: Write failing tests** with `FakeTime`, `FakeAudio`, the vectors programme, and a synced `ProgrammeClock`:
  1. `start()` sets `current.src` to the target track's `audio`, waits for `canplay`, seeks to the **recomputed** target (time passed while loading), calls `play()`, and reports `onPlaying`.
  2. Drift: after start, force `currentTime` +500 ms; run 60 simulated seconds of 1 s ticks (with `FakeAudio.tick`); `|err|` ends < 40 ms, no seek recorded, `playbackRate` back to 1.
  3. `err` includes output latency: with `outputLatencyMs = 100` the engine keeps the element 100 ms *ahead* in the file, because the sound it outputs now is heard 100 ms later.
  4. Large error (+1500 ms) → exactly one seek.
  5. Stall: dispatch `waiting` then `playing` after 2 s of simulated time → one seek to the new target.
  6. Preload: when `msToNextTrack < 30000`, `next.src` is set to the next track's audio and `load()` is called once.
  7. Boundary: when the programme clock crosses into the next track, `next` becomes `current`, seeks to `posInTrackMs`, plays; the old element is paused and becomes `next`. Also crosses the loop boundary (last track → first).
  8. `rateMax = 0`: `playbackRate` never leaves 1 over the whole drift test; the seek happens only when `isInGap` is true.
  9. `stop()` pauses and clears timers.
- [ ] **Step 2: Run to verify they fail.**
- [ ] **Step 3: Implement** `new AudioEngine({ programmeClock, compiled, getTimings, createAudio, outputLatencyMs, rateMax, deps })`. Correction tick every 1000 ms; `errMs = current.currentTime × 1000 − (target.posInTrackMs + outputLatencyMs)`. Emit `onTick({ trackIndex, posInTrackMs, errMs, rate })` for the store. Set `preservesPitch = true` on elements (so a rate nudge never changes pitch).
- [ ] **Step 4: Run to verify they pass.** · **Step 5: Commit** — `Add audio engine with drift correction and track changes`
