# Plan 07: Deploy and Operations Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything needed to deploy and run the MVP for at most $20/month, prepared so that the human only has to paste credentials (Manual Part 2): the API container, Railway config, the Cloudflare Pages workflow and headers, a 5,000-client load test with an egress cost estimate, and a runbook.

**Architecture:** The API ships as a tiny static Go binary in a distroless image that Railway builds from `apps/api/Dockerfile`. The web app is uploaded to Cloudflare Pages by a GitHub Action using `wrangler`. The load tester is its own Go module that speaks protocol v1 exactly like a browser and measures bytes received per client, which is Railway's billed egress.

**Tech stack:** Docker (multi-stage), Railway config-as-code, GitHub Actions, `cloudflare/wrangler-action`, Go 1.24 (`github.com/coder/websocket`).

**Owns:** `apps/api/Dockerfile`, `apps/api/.dockerignore`, `railway.json`, `.github/workflows/deploy-web.yml`, `.github/workflows/ci.yml` (adds a job), `apps/web/public/_headers`, `tools/loadtest/`, `docs/RUNBOOK.md`.

**Depends on (merged):** plans 03 and 05.

**Spec sections:** §1 (S7, S8), §3, §6. Manual steps it prepares: M-E4, M-E5, M-E6, M-E7.

### Task 1: API container

**Files:** Create `apps/api/Dockerfile`, `apps/api/.dockerignore`

- [ ] **Step 1: Write**
```dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.24-alpine AS build
WORKDIR /src
COPY apps/api/go.mod apps/api/go.sum ./
RUN go mod download
COPY apps/api/ ./
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/server ./cmd/server

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/server /server
ENV PORT=8080
EXPOSE 8080
USER nonroot:nonroot
ENTRYPOINT ["/server"]
```
The build context is the repo root (Railway root directory `/`).
- [ ] **Step 2: Verify** — `docker build -f apps/api/Dockerfile -t tilawah-api .` then `docker run --rm -p 8080:8080 tilawah-api` and `curl localhost:8080/healthz` → `ok`; image under 25 MB. If Docker isn't available in the environment, add the CI job in Task 2 and rely on it.

### Task 5: Web deploy workflow

**Files:** Create `.github/workflows/deploy-web.yml`

- [ ] **Step 1: Write**
```yaml
name: deploy-web
on:
  push:
    branches: [main]
    paths: ["apps/web/**", "packages/**", "pnpm-lock.yaml", ".github/workflows/deploy-web.yml"]
  workflow_dispatch:
concurrency: { group: deploy-web, cancel-in-progress: true }
jobs:
  deploy:
    if: ${{ vars.SITE_DOMAIN != '' }}
    runs-on: ubuntu-latest
    permissions: { contents: read, deployments: write }
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version-file: .nvmrc, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm data:validate
      - run: pnpm --filter web build
        env:
          NEXT_PUBLIC_API_URL: ${{ vars.NEXT_PUBLIC_API_URL }}
          NEXT_PUBLIC_WS_URL: ${{ vars.NEXT_PUBLIC_WS_URL }}
          NEXT_PUBLIC_RATE_NUDGE_MAX: ${{ vars.NEXT_PUBLIC_RATE_NUDGE_MAX || '0.02' }}
      - run: sed -i "s/__DOMAIN__/${{ vars.SITE_DOMAIN }}/g" apps/web/out/_headers
      - uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: pages deploy apps/web/out --project-name=tilawah --branch=main
```
The job is skipped until `SITE_DOMAIN` exists (M-E6 adds it along with the other variables), so it never fails before setup.
- [ ] **Step 2: Commit** — `Add Cloudflare Pages deploy workflow`

### Task 6: Load tester

**Files:** Create `tools/loadtest/go.mod`, `tools/loadtest/main.go`, `tools/loadtest/client.go`, `tools/loadtest/report.go`, `tools/loadtest/client_test.go`

- [ ] **Step 1: Write the failing test**: start an in-test `httptest` WebSocket server that answers `hello` with `welcome` and `ping` with `pong`, and counts bytes written. Run the client for simulated durations with a compressed schedule (`-hb 100ms -resync 300ms -stat 200ms`), and assert: `hello` first, an 8-ping burst, `state{playing:true}`, periodic `hb`/`stat`/3-ping bursts; `BytesReceived` equals what the server wrote; pong latencies are recorded.
- [ ] **Step 2: Run to verify it fails.**
- [ ] **Step 3: Implement.** Flags: `-url`, `-n` (clients), `-ramp` (duration to spread connects), `-duration`, `-origin`, `-secret` (sets `X-Origin-Auth`), `-anon-ratio` (default 0.2), `-country` list to fake `cf-ipcountry`/`cf-iplatitude`/`cf-iplongitude` headers (only meaningful against a local server with `TRUST_CF_HEADERS=true`), and the three schedule flags with production defaults (45 s, 5 min, 60 s). The report prints: connected, failed, disconnected, pong latency p50/p95/p99, total and per-client bytes received per minute, and the extrapolated monthly Railway egress for 5,000 always-on listeners at $0.05/GB:
  ```
  egressGB/month = perClientBytesPerMin × 60 × 24 × 30 × 5000 / 1e9
  ```
  plus the snapshot fetch cost (one ~5 KB gzip body per 10 s per Cloudflare upper tier, assume 5 tiers).
- [ ] **Step 4: Run to verify it passes.**
- [ ] **Step 5: Local 5,000-client run** — raise `ulimit -n 65535`, start the API with `STATS_TOKEN=local MAX_CONNS_PER_IP=100000`, run `go run . -url ws://localhost:8080/v1/ws -n 5000 -ramp 60s -duration 10m -origin http://localhost:3000`. While it runs, read `/v1/stats` for memory. Record the results in `tools/loadtest/RESULTS.md`: RSS (S8: < 400 MB), p99 pong (< 50 ms), per-client bytes/min, and the monthly egress estimate (S7). If egress is over $5/month, stop and report which message dominates.
- [ ] **Step 6: Commit** — `Add WebSocket load tester and local results`
